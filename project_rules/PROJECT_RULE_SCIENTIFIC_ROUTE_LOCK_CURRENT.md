# Owner 科研路线锁与变更控制

更新：2026-09-18。锁：`DLH-WL-V1-20260918`。

## 1. 权威来自 Owner，不来自模型版本

Owner 已明确批准 `docs/decisions/DLH_OWNER_ROUTE_FREEZE_WL_V1_2026_09_18.md` 中的路线。GPT-5.6、GPT-6、DSH 或其他 agent 均不得因新会话、配额变化、模型切换、偏好另一算法、历史文档或一次失败自行重排路线。

**默认动作是继续已批准规划，而不是每次接手重新规划。**“Reviewer 认为更合理”不能取代 Owner 对战略变化的批准；Owner 的一般性“继续”“修复问题”不自动解除明确锁定项。

## 2. 两层变更权限

锁定项：首学对象及经济含义、给定外流比例与总劳动的边界、矩阵方向/守恒、家庭冻结及未解状态、solver 暂停、离线与经济耦合的依赖关系、资本/名义/Results 后置、项目边界与证据标准。改变任何一项须 Owner 明确批准。

Reviewer 可在不触及锁定项的前提下，发布 bounded Issue，事前确定小网络、优化器、tiny fixture、度量、预算与实现细节；接受后更新进度指针。DSH 可在 Issue 内做等价工程修复、日志与聚焦测试。实验已经启动后不得看结果修改目标、数据划分、方法或阈值。

拼写、链接、已验收进度、路径更名的等价映射等低风险修改不需要重新审批整条路线。

## 3. 有证据才能提出战略变更

先报告：现有锁定条款、最小反例/新证据、影响哪个 claim、是否仅能局部修复、建议差异、成本/替代路线。重大科学错误出现时立刻暂停受影响工作；不为遵守旧计划继续产生不可信结果，也不擅自换模型。

Owner 明确批准后，新建 dated decision/amendment，保留旧决定，列出逐条 supersession，再同步路线/合同/任务。不得先改路线或哈希，再补造“Owner 已同意”。无批准时可保存建议，当前路线不变；无关低风险工作不必一起停止。

## 4. 防漂移检查

`docs/governance/DLH_ROUTE_LOCK_MANIFEST.json` 记录原始 adoption 文件的完整 SHA-256/Git blob，以及 Roadmap 的 OWNER_LOCKED_ROUTE 区块 SHA-256。区块以标记包围、UTF-8/LF、含结束标记后的换行计算。

同步只需静态计算这些内容哈希，不跑模型。Manifest 本身受同一 Owner 变更边界保护，不得更新哈希以掩盖无授权修改。原始 dated adoption 保持不变；合法 amendment 使用新版本记录。

Roadmap 区块之外允许已验收进度更新，不能把“进度更新”作为改变锁定语义的借口。新科学任务必须注明 route ID 并声明未改变锁定项。

这是审计与工作流保护，不是 GitHub 服务器端 branch protection；不声称能阻止所有越权写入。本轮不修改仓库管理员权限或 branch protection。
